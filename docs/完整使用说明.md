# 分镜调度台 · 俯视图走位与运镜工具

一个**纯本地、零依赖**的小工具：铺一张俯视背景图当"地面"，在上面摆角色块、拉走位线、给动作、架摄像机调运镜，最后导出**俯视调度图**和**镜头视角视频**。

- **3D / 2D 双模式**：3D 是透视投影（消失点 + 立体人物）；2D 是正交投影立面侧视图（无透视 + 平面剪影 + 米制参考线）。
- **两种视图**：俯视编辑（编排走位）+ 3D 观察（拖动环绕看立体效果）。「画面」开关只管成片画面，不干扰这两个编辑视图。
- **镜头预演**：大窗口实时播放整段镜头，可播放/拖动/循环，直接在窗口里录制成片；右下角小预览**双击可放大**细看。
- **导出可选位置**：默认记住一个文件夹，之后出片不再每次弹窗；按 `Shift` 点导出按钮可临时另存为。
- **44 个动作模板**：基础 / 转身 / 打斗 / 剧情四组，从连续出拳、高踢腿、回旋踢，到拥抱、打电话、单膝跪地，以及左转 / 右转 / 面向镜头。
- **22 个运镜模板**：基础 / 跟随环绕 / 大片三组，含**希区柯克变焦**、环绕一圈、螺旋推进、低角度仰拍、顶视俯拍、手持晃动。
- **AI 编排**（可选）：接你自己 ComfyUI 里的本地模型（llama-cpp），用一句中文改分镜 ——
  「男主从左边走到中间，打一套连续拳」「把女主往左挪 2 米」。

双击 `index.html` 就能用（不需要装任何东西、不需要联网）。
AI 编排是**可选增强**，不装也不影响其他功能。

## 3D / 2D 与两种视图

这里有两组开关，管的是完全不同的两件事：

| 切换 | 位置 | 说明 |
|---|---|---|
| **画面：3D 透视 / 2D 平面** | 顶栏 | 管的是**镜头拍出来长什么样**。3D＝透视投影，地面有消失点、人物有体积和受光渐变，远处自然变小；2D＝正交投影立面侧视图，没有消失点、没有透视地面，人物是永远正对镜头的平面剪影，像分镜草图，画面里还带 `1m…8m` 高度参考线和相机视高线。 |
| **舞台：俯视编辑 / 3D 观察** | 舞台左上角 | 管的是**你在编辑器里从哪个角度看**。俯视用来编排走位（拖拽、画线、改路径最直观）；3D 观察用来看空间关系。 |

**「画面」开关的作用范围**：镜头预览、预演播放器、导出镜头图、导出视频——也就是**所有"成片画面"**。
它**不影响**俯视编辑和 3D 观察这两个编辑器视图：俯视是编排用的符号视图，3D 观察永远是立体场景
（如果让 3D 观察也跟着切成平面剪影，那些薄片被侧着看会变成贴地的细棍，看着像坏了）。

> 舞台左上角的 HUD 会常驻显示当前画面模式（如 `镜头画面 2D 平面`），切完可以立刻核对。
> **在俯视编辑下切 3D/2D，大舞台看起来不会变**——这是对的，俯视图画的是俯视符号（圆 + 朝向楔形），
> 与"镜头拍成什么样"无关。要看差别请切到 **3D 观察**舞台，或者直接看右栏的**镜头预览**。

**3D 观察视图的操作**：拖动＝旋转视角，滚轮＝推拉，`Shift`+拖动或中键拖动＝平移。
在 3D 视图里也能直接**选中并拖动角色**（鼠标射线打到地面来定位），摄像机画成"地面标记 + 高度线 + 头顶球"，一眼看出机位架多高。

### 2D 平面视角是怎么画的

不是"把俯视背景图压扁"，而是**正交投影的立面侧视图**：

- 横向：角色相对相机的左右偏移，线性映射到屏幕 x（`x = W/2 + lat × s`）
- 纵向：世界高度线性映射到屏幕 y，脚底统一落在地面线（画面高度 70% 处）
- **没有缩放**：远处的人物不会变小（正交投影的定义），只用轻微雾化做深度提示，由远到近叠着画
- 取景标定：以 8m 参考距离定标 `s`，并把 1.75m 人物高度夹在画面的 8%～70% 之间，保证不同 FOV 下取景都合理
- 画面里画了 `1m…8m` 高度参考线和相机视高虚线，方便直接目测人物和机位的高度关系

由于 hpx（站立身高像素）在两种模式下都按 `身高(m) × pxPerMeter × 缩放` 算，
**人物在 2D 平面画面里的高度就是配置身高本身**（实测：配 1.75m 画出来 1.74m，误差来自姿态前倾）。

## 怎么看出人物朝哪儿

朝向是**看图才知道**的东西。数值上 `angle` 一直是对的，但「画出来能不能一眼分出正反」
得把多个方向并排放在一起才看得出来 —— 单个角色在默认缩放下只是一个 10px 的圆。

所以这里做了**三层标记**，按你看的远近各管一段：

| 层 | 出现位置 | 长什么样 | 管什么距离 |
|---|---|---|---|
| **视线扇形** | 俯视编辑 + 预演（勾「视线」时） | 从脚下铺出去的半透明扇形，半径 4m、半张角 32° | 远看：一眼看出"这片区域在它的视野里" |
| **箭头 + 鼻尖弧** | 俯视编辑 | 圆外一支带白描边的箭头 + 圆上一段加粗白色弧（鼻尖） | 中景：不放大也能分出八个方向 |
| **肩线 / 脚尖 / 鼻尖 / 两眼** | 3D 透视 / 3D 观察 | 见下 | 放大看：正脸、后背、侧面各不相同 |

### 俯视图为什么用「箭头 + 视线扇形」

圆本身**没有任何方向信息**（转多少度轮廓都一样），所以以前那个"圆 + 朝向楔形"在默认缩放下
几乎看不出朝向。现在：

- **箭头从圆上离开**（箭杆 `0.98r → 1.40r`，三角尖到 `2.10r`），并且**描一圈白底** ——
  角色颜色再浅、背景再花，箭头都还在。
- **鼻尖弧**：圆上正前方 ±34° 画一段加粗白弧，把"哪边是脸"直接标在圆上。
- **旋转手柄让开箭头**：手柄距离改成 `2.10r + 16`，压在箭头上就会既挡视线又容易误点。
- **视线扇形**（可开关）：半径 `4m × pxPerMeter`、半张角 `32°`，共 20 个点（顶点 + 19 个弧点）。
  它铺在角色**下面**（不然会把小人盖住），是**地面图形** —— 透视下会投到 z=0。

> 「看不清」有一半是**尺寸问题**：默认缩放下圆只有 10px，箭头再清楚也挤在一起。
> 所以顺带把**镜头预演窗口做成可缩放的**（见下面 ⑥）。

### 3D 里为什么能分出正反

3D 人物是**圆柱段 + 球头**：绕自身轴转一圈，轮廓完全不变。不加东西的话正脸、后背、侧面
在 3D 里长得一模一样。所以补了四个**不对称特征**：

- **肩线**：躯干上横着一条（沿 v 轴），轮廓从"一根柱子"变成"头 + 肩 + 身"的 T 形。
- **脚尖**：脚踝往前伸一小截，朝 +u（人物正前方）。
- **鼻尖**：头前面凸一个球。**按深度决定画在头前还是头后** ——
  背对镜头时鼻尖在头的**远侧**，必须先画鼻尖再画头，否则它会穿到脸前面、把朝向说反。
- **两眼**：只在**正脸朝镜头**时画，用「朝向 · 镜头前向」的点积淡入淡出。
  侧面和背面自然就看不见眼睛。

效果可以直接看 `截图/朝向/朝向_3D四方向.png`：正对镜头有两只眼、背对是光球、
朝东鼻子朝右、朝西鼻子朝左。

## 制作流程

### ① 铺地面
- **导入背景图**：任何俯视图都行（小区平面图、仓库顶视图、手绘方格纸、游戏地图截图）
- **示例背景**：一键生成"街道"或"广场"（再点一次会切换另一种）
- 比例尺默认 `50 px = 1 米`，可在右侧属性面板改（影响人物身高、镜头高度的真实感）

### ② 摆角色
- 顶栏 **＋角色** 或按 `2`，在图上点一下就放下一个
- 拖动角色块移动位置；拖**圆环外的小球**改朝向
- 右侧可改名字、颜色、身高、体宽

### ③ 画走位线
- 先**选中角色**，再按 `4` 切到「画走位线」
- 在图上依次点击，`回车` 或**双击**结束（`右键`退掉上一个点）
- 角色会沿这条线按**弧长匀速**移动，默认 2.5s，可在属性面板改时长/缓动
- 想改路径：拖线上的蓝色方块；选中片段后右键路径点可删除
- 不想手画：左侧「走位模板」有直线前进 / 后退 / 横向平移 / 折线突进 / 弧线绕行 / 环绕一圈

### ④ 加动作
选中角色 → 左侧「动作模板」点一下，动作片段就插在**当前播放头**位置。

动作面板按用途分了 **4 组共 44 个**，每组标题可点一下收起 / 展开（收起状态只在本次会话里记着）：

**基础（7）**

| 动作 | 时长 | 类型 | 说明 |
|---|---|---|---|
| 站立待机 | 2.0s | 循环 | 呼吸起伏 |
| 走路 | 2.0s | 循环 | 双腿交替 + 反向摆臂 |
| 奔跑 | 1.2s | 循环 | 大步幅、躯干前倾、腾空 |
| 冲刺 | 0.9s | 循环 | 比奔跑更快的步频 + 躯干压到 26° |
| 跳跃 | 0.8s | 单次 | 抛物线腾空 + 落地缓冲 |
| 蹲下 | 0.6s | 保持 | 屈膝下沉，脚仍踩地 |
| 坐下 | 0.8s | 保持 | 重心下移到椅高、双腿前伸 |

**转身（6）** —— 改的是**朝向**，不是姿态

| 动作 | 时长 | 说明 |
|---|---|---|
| 左转 90° / 右转 90° | 0.6s | 按角色**自己的左右手**转（= 朝画面左 / 右转） |
| 左转 180° / 右转 180° | 0.9s | 同上，转半圈 |
| 转身面向镜头 | 0.8s | 转到 180°（正对观众） |
| 转身背对镜头 | 0.8s | 转到 0°（背对观众） |

> 这几条和别的动作不一样：它们不摆姿势，而是插一段**转身片段**（和拖着角色旋转手柄、
> 以及 AI 的 `face` 操作走的是同一条路）。相对角度按**当前朝向**算，
> 所以连点两次「右转 90°」会真的转两次。
> 角度约定：`0° = 背对观众`，顺时针为正；`+90° = 画面右`，`180° = 面向观众`，`-90° = 画面左`。
>
> **转身方向是「存下来的」，不是「算出来的」**：片段里除了起点 `from` 和终点 `to`，
> 还显式存一个**有向扫角 `sweep`**（`+π` 就是往画面右扫半圈，`-π` 是往左），
> 求值时按 `from + sweep × 缓动` 插值。为什么必须这样：通用的角度插值走的是**最短弧**，
> 而 **±180° 恰好是最短弧的歧义点**（`+π` 和 `-π` 归一后都是 `-π`），
> 于是「右转 180°」和「左转 180°」会双双扫向同一侧 —— 两个按钮做出同一个效果。
> 更麻烦的是**只看终点发现不了**（±180° 本来就是同一个方向），必须量中间时刻
> （`sweep` 修好后：右转 180° 的中点 `+90°`、左转 180° 的中点 `-90°`）。
> `to` 和 `sweep` 是**解耦**的：`to` 保留模型/界面给的绝对方位（可能是 `270°` 这种值），
> `sweep` 单独记方向。老工程里没有 `sweep` 字段，会回退到最短弧插值。

**打斗（16）** —— 动作片那种连续攻防

| 动作 | 时长 | 类型 | 说明 |
|---|---|---|---|
| 出拳 | 0.5s | 单次 | 单记直拳，肩部前送 |
| 连续出拳 | 1.6s | 循环 | **四记组合拳**（右-左-右-左），窗口首尾重叠，读起来是连续输出而不是四下单练 |

### ⑤ 架摄像机 + 运镜
- 顶栏 **＋摄像机** 或按 `3`，在图上点一下
- 选中摄像机后：拖**机身**移动、拖**前方小球**改朝向、拖**紫色虚线框的角点**改视场角
- 右侧面板可精调：朝向 / 俯仰 / 高度 / 视场角
- 俯视图上那个**紫色虚线四边形**就是这台摄像机的**地面视野范围**，框住哪里就拍到哪里
- 右侧「镜头预览」实时显示成片画面

**运镜模板**（选中摄像机 → 左侧点一下，会生成关键帧）也分了 **3 组共 22 个**：

**基础（10）**

| 模板 | 效果 |
|---|---|
| 固定镜头 | 清掉该时间之后的关键帧，保持不动 |
| 横摇 45° →/← | 朝向在时长内转动 |
| 推进 / 拉远 | 沿镜头朝向前进/后退 3m |
| 横移跟拍 | 侧向平移 3m，朝向不变 |
| 俯仰 | 俯仰角 → 45° |
| 变焦推近 | 视场角 60° → 28° |
| 急推 | 0.45s 内视场角砍到 40%，用来强调一个反应 |
| 甩镜 | 0.35s 内急转 140° |

**跟随 / 环绕（5）**

| 模板 | 效果 |
|---|---|
| 跟随角色 | 摄像机自动跟在角色身后并看向目标 |
| 越肩 | 跟随 + 侧向偏移 0.7m（对话戏经典机位） |
| 环绕一圈 | 以主体为圆心**绕满 360°**（9 个关键帧，全程看向主体，走**真圆弧**不是折线） |
| 螺旋环绕推进 | 边绕一整圈边靠近到 45% 距离、高度降到 1m、视场角放到 65%（**螺旋弧**） |
| 弧形上升 | 绕 126° 同时升到 6m 并后退，收尾拉出全景（**弧形**） |

> 三个环绕类运镜走的是**真圆弧**（关键帧上挂了圆心 `arc`，段内按极坐标插值），
> 不是把关键帧用直线连起来。后者是内接多边形：段中点到圆心只有 `0.924R`，
> 镜头会忽远忽近、主体在画面里大小脉动 7.6%，周长也只有真圆的 `97.45%`。
>
> ⚠️ **环绕类的圆心是"套模板那一刻"按主体位置算出来的，之后不会跟着主体走。**
> 如果角色在环绕期间走动，镜头绕的是**它出发时的位置**，不是它当前的位置。
> 想一直盯住走动的角色，用**跟随角色**（但那样就没有自主环绕了）——
> 「跟随」和「关键帧」目前是互斥的，见下面的说明。

**大片手感（7）**

| 模板 | 效果 |
|---|---|
| **希区柯克变焦** | 推近的同时**放大**视角：主体在画面里大小不变，背景被「抽走」（眩晕效果） |
| 希区柯克变焦（反向） | 后退的同时收窄视角：主体大小不变，背景反而被推近 |
| 低角度仰拍 | 机位降到 0.55m、镜头上仰 5°，人物显得高大 |
| 顶视俯拍 | 升到 14m 近乎垂直向下拍，上帝视角 |
| 升降 | 高度 1.6m → 4.5m |
| 摇臂下降 | 先升到 6.5m 再缓缓降回平视 |
| 手持晃动 | 轻微无规律抖动，纪实质感（固定种子，同一段每次生成都一样） |

> 套模板会**截断当前时间之后的关键帧**再追加，所以按时间顺序一段段叠就行。
> 也可以自己画：选中摄像机用「画走位线」画一条，会沿路径生成一串关键帧，镜头自动沿路径朝向。
> 摄像机有关键帧时，在舞台上拖动会**自动在当前时间打关键帧**。
>
> **「跟随」和「关键帧」是互斥的两种控制方式**，只能二选一：
> 「跟随角色 / 越肩」让摄像机每帧跟着角色走（位置由目标算出来，不看关键帧）；
> 其它所有运镜都是**关键帧**驱动的自主运动。
> 往一台正在跟随的机位上套自主运镜（环绕一圈 / 推进 / 横摇…）时，
> **关键帧赢、跟随自动让位**，并在提示里写明「已关闭跟随、改用关键帧」。
> （反过来不这样做的话，跟随会每帧把关键帧算出来的位置整个覆盖掉 ——
> 键全都在、画面纹丝不动，看起来就像「这个运镜没生效」。）
>
> 同一台机位在同一时刻再套一次运镜，会**切掉前一段的后半截**（这是正常行为，
> 后一条本来就该覆盖）。这时候提示里会点名被覆盖的是哪一段，别以为两条都加上了。
>
> **希区柯克变焦是怎么实现的**：主体在画面里的大小 ∝ 1 /（tan(视场角/2) × 距离），
> 所以让 `tan(视场角/2)` 与距离成反比，主体就锁死了，画面变化全落在背景上。
> 注意这里必须用 `tan` 而不是直接按角度等比缩放 —— 小角度近似会差出好几倍。

### ⑥ 预览镜头视频
顶栏点 **「预览镜头视频」** 打开大窗口预演：

- 播放 / 暂停 / 归零 / 拖进度条 / 循环
- 分辨率可单独设（640×360 ~ 1920×1080），**辅助线**可开关
- **视线**：叠加角色视线扇形（编辑标记，见上面「怎么看出人物朝哪儿」）
- **缩放**：`－` / `＋` / 百分比 / **适应**；滚轮缩放、拖动平移
- **存当前帧**：把当前画面存成 PNG
- **录制并导出**：直接按当前模式（3D/2D）和分辨率出片

> **看清细节**：右下角那块小镜头预览太小、看不清人和朝向时，**双击它**就弹出「放大观察」
> （一个占满窗口的大浮层）。里面可以滚轮缩放、拖动平移，`1:1` 按钮直接按像素 1:1 显示，
> 并**自动对准主体**（不是图像几何中心 —— 画面里人往往偏在一侧，按几何中心放大会把人推出视野）。
> 还可以**存当前帧**。按 `Esc` 或再双击浮层空白处退出。
> 这个浮层是纯查看，**不会改动工程**。

> 预演窗口和主时间轴**共用同一个播放头**——你在哪儿停下，导出的就是那一段。

> **缩放只改「显示尺寸」，不改画布分辨率。** 也就是说放大只是让你看清（尤其是小人和朝向），
> 存当前帧和录制出来的成片仍然是你在分辨率里选的那个尺寸，不会跟着变小或变糊。
> 缩放以**指针为锚点**（滚轮指着哪个位置，那个位置就钉在原地不动），切换分辨率会自动重新「适应」。
> 拖动平移只在画面比视口大时才起作用。

## AI 编排（用你自己的本地模型改分镜）

顶栏 **「AI 编排」** 按钮。你打一句中文，本地模型把它翻成操作，直接改到场景上。

> 这是**可选功能**。不启动它，工具仍然是纯静态双击可用。

### 怎么用

1. 先让 **ComfyUI 跑起来**（本地模型就在它里面）—— 或者跳过这步，用云端 API
2. 双击工具目录下的 **`启动AI.bat`** —— 它会另开一个窗口起代理，然后自动打开分镜调度台
   （那个代理窗口要一直开着）
3. 顶栏点 **「AI 编排」**，面板顶部会显示当前通道、模型名和忙闲状态
4. 选 **「写入方式」**（见下），输入一句话，点 **「生成并应用」**（或 Ctrl+Enter）

### 两条通道，随时切

面板里的 **「设置 · 用哪个模型」** 展开就能切：

| 通道 | 适合 | 代价 |
|---|---|---|
| **本地 ComfyUI** | 免费、数据不出本机、模型你自己挑 | 要排队；和视频任务抢 ComfyUI 队列 |
| **云端 API**（任何 OpenAI 兼容端点） | 快、不用显卡、模型能力强 | 要 API Key、按量计费 |

云端那边填 **Base URL / API Key / 模型名** 三项就能用，另有温度、`max_tokens`、
JSON 模式、流式四个开关。填完点 **「测试连接」** —— 它会先保存再发一句极短的话试通。

> **Key 只写在本机 `ai-config.json`**，不会发到浏览器（前端拿到的永远是打过码的版本）。
> 想换 Key 就直接覆盖，想清掉点旁边的「清除」。

支持的端点举例：`https://api.deepseek.com/v1`、`https://api.openai.com/v1`、
各种中转/自建（只要兼容 `/chat/completions`）。**Base URL 要填到 `/v1` 为止。**

### 写入方式：接在后面，还是整场替换

面板上的「写入方式」决定这批操作落在时间线的哪里：

| 方式 | 效果 |
|---|---|
| **就地修改**（默认） | 在现有分镜上直接改 |
| **接在后面** | 新内容**接在已有时间线末尾**，已有内容一个都不动 |
| **整场替换** | 先清空角色/机位/片段，再从头搭（会弹确认框） |

「接在后面」的实现值得一提：**模型并不知道时间线末尾在第几秒**。
不让它去算 —— 它照常「从 0 秒开始写一条新片段」，由工具在应用前
把整批操作的时间字段整体加上一个基准 `T`。

> 为什么必须在**应用之前**加：`shot` 会用它的开始时间去**切掉**那之后的关键帧。
> 如果拿 `at=0` 去切，已有的运镜会被整个删掉。先把它改写成 `at=T`，
> 切割点才落在正确的位置。

### 在已有运镜上继续叠加

先说「镜头后拉」，下一个对话再说「**在后拉的同时往上升一点**」——
这时候不该新建一段运镜，而要在原来那段的运动上叠加上升。

工具为此有一个专门的操作 `camMove`：让机位在一段时间里沿某方向线性移动
`meters` 米，之后保持。方向可以是 `up` / `down`（改机位高度），
也可以是 `north` / `south` / `east` / `west` 等（改水平位置）。

```
第 1 轮  镜头从正面往后拉远一点        → shot dollyOut
第 2 轮  让这个镜头在后拉的同时往上升一点 → camMove dir=up meters=1.5
```

结果（机位属性面板里能直接看到）：

```
0.00s  X10.8  Y20.1  H1.6       ← 起点
2.50s  X10.8  Y23.1  H3.1       ← Y 变大 = 后拉；H 变大 = 同时升高
```

> 关键区别：**`shot` 是「生成一段新运镜」，会删掉它开始时间点之后的旧关键帧**；
> **`camMove` 是在旧关键帧上做偏移**，两者能叠在一起。
> 该用 `camMove` 的时候用了 `shot`，你前面调好的运镜就没了。

**`camMove` 不用报秒数**：省略时间，它会自动对齐到这台机位**最近一段运镜**的窗口上
（起止都对齐），日志里会写清叠在哪一段 ——

```
✓ camMove — 「机位1」在 4.1~6.6s 抬高 1.5m（叠在最近一段运镜「拉远」上）
```

只有你明确说「从第 5 秒开始升 3 秒」时才会用到显式秒数；那种情况下如果这段和
已有运镜完全不重叠，日志会提示「（注意：这段没和已有运镜重叠）」，免得你以为叠上了。

### 能听懂什么

| 说法 | 落到什么 |
|---|---|
| 男主从左边走到中间 | 走位片段（west → center） |
| 打一套连续拳 / 高踢腿 / 深情看着男主 | 动作片段（combo / highKick / face 指向角色） |
| 加一个女主站在右边 | 新角色（east 锚点） |
| 把女主往左挪 2 米 | 平移（走位路径一起移） |
| 结尾环绕男主转一圈 | 运镜片段（orbit，跟随男主） |
| 镜头一边后拉一边往上抬 2 米 | 运镜（dollyOut）+ 叠加上升（camMove up） |
| 让这个镜头在后拉的同时往上升一点 | 只叠加上升，不动原来那段运镜 |
| 加一台机位在正面，跟随男主 | 新机位 + follow |
| 时长改成 12 秒 / 名字叫巷战 / 换广场背景 | 工程设置 |
| 删掉女主 / 清空男主的动作 | 删除 / 清空 |

**方位词**用 `center / north(远) / south(近) / west(左) / east(右)` 加四个角，
中文（左/右/远处/近处/背对观众…）也认。

### 它是怎么工作的（为什么不让模型直接写存档）

存档里的坐标是**背景像素**，还夹着 `keys` / `clips` 这些深层结构。
8B 模型算不准像素，也背不住这么深的结构 —— 直接让它吐存档 JSON，失败率会很高。

所以中间加了一层**意图 DSL**：模型只说「谁、做什么、在哪个方位、第几秒」，
方位用 `center` / `north` 这类词，**由工具换算成像素**。
模型要输出的东西越少，出错率越低。

```
浏览器（file:// 页面）
   │  POST http://127.0.0.1:8790/llm   ← 浏览器自己组 prompt
   ▼
ai-proxy.js（Node，零依赖）
   ├ 通道 A  本地 ComfyUI
   │   1. 提交 4 节点工作流到 ComfyUI /prompt
   │      llama_cpp_model_loader → llama_cpp_parameters
   │      → llama_cpp_instruct_adv → PreviewAny
   │   2. 轮询 /history 拿文本
   └ 通道 B  云端 API
       1. POST {baseUrl}/chat/completions（SSE 流式，边收边报进度）
   │
   │  剥  thinking、剥代码围栏、找平衡括号、修尾逗号
   ▼
返回 JSON → 校验 → 按写入方式换算时间 → 逐条应用 → refreshAll()
```

三个必须知道的实现细节：

- **为什么非要一个代理**：页面是 `file://` 打开的，Origin 是字符串 `null`，
  而 ComfyUI 完全不发 CORS 头 → 浏览器直连必被挡。代理还顺手把
  「提交 + 轮询」两段式协议包成一次调用，并把两条通道统一成同一个接口。
- **为什么工作流末尾要挂一个 `PreviewAny`**：`llama_cpp_instruct_adv` 返回的
  STRING 没带 `ui` 字段，ComfyUI 不会把它放进 `/history` 的 `outputs`。
  加一个 KJNodes 的 `PreviewAny`（它是 output_node）才能把文本读回来。
- **为什么给 Qwen3 加 `/no_think`**：思考模型会把预算耗在推理上，
  提示词一复杂就「思考写满、JSON 一个字没吐」。实测同一句话
  **5.1s / 377 字 → 1.5s / 37 字**，也不再截断。非 Qwen 模型不加。
  面板设置里可以强制开/关。

### 限制（都是真的，先说清楚）

- **会和视频任务抢队列**（仅本地通道）。ComfyUI 的 `/prompt` 是先进先出，
  你正在跑视频时 AI 请求会排在后面。面板会显示「⚠ ComfyUI 正在跑别的任务」
  和实时排队位置。等不及点「取消」——**只会撤掉自己排队的那个**，
  绝不打断你正在跑的视频。
- **一次只跑一个 AI 请求**（代理内部串行），不会把队列灌满。
- 模型偶尔会认错角色名或写错动作 id。**单条失败不影响其他条**，
  面板会逐条列出 ✓/✗，不满意按 **Ctrl+Z** 撤销（整批只占一个撤销点）。
- **本地通道**首次请求要加载模型（实测约 10 秒），之后模型常驻，
  单次 **1~3 秒**（关掉思考后）。**云端通道**取决于对方，通常 1~5 秒。
- **「整场替换」是不可逆的一步**，会弹确认框。撤不回来的话按 Ctrl+Z。
  （一条都没落地时会**自动整体还原**，不会出现「旧场景没了、新场景也没搭起来」。）
- **跟随机位与自主运镜互斥**：往正在跟随的机位上套运镜，跟随会自动关闭并提示。
- **跟随机位的 `camMove` 上下是阶跃**（直接改跟随高度，做不出渐变）；
  **水平方向会关掉跟随**（跟随位置由目标决定，横移改不了它），日志里会说明。
- 同一台机位同一时刻再套一次运镜，会**切掉前一段的后半截** —— 正常行为，但会点名提示。
- **环绕类的圆心是静态的**：套模板那一刻按主体位置算出来，之后不跟着主体走。
  角色边走边环绕的话，镜头绕的是它出发时的位置。想盯住走动的角色只能用**跟随角色**，
  而跟随和关键帧是互斥的（即：目前做不出「一边环绕一边追着走动的角色」）。

## 界面速览

```
┌─ 顶栏：导入背景 / 示例 / 角色 / 摄像机 / 保存打开撤销 / 时长帧率 / 导出 ─┐
├──────────┬────────────────────────────────┬──────────────┤
│ 工具      │                                │ 属性面板      │
│ 动作模板  │        俯 视 舞 台              │ （按选中对象）│
│ 走位模板  │  背景·角色·走位线·镜头视野框     │──────────────│
│ 运镜模板  │                                │ 镜头预览      │
│ 图层      ├────────────────────────────────┤ （实时画面）  │
│          │ 时间轴：播放头 · 色条 · 关键帧   │              │
└──────────┴────────────────────────────────┴──────────────┘
```

时间轴：**拖色条**改开始时间，**拖色条右缘**改时长，**拖播放头**（或在轨道上拖）定位时间；
**双击色条**跳到这一段的开头；摄像机的关键帧是紫色小菱形，可拖动改时间。

> 时间轴觉得太窄、色条老是点不到？**拖时间轴顶边那条横杠就能把它拉高**（往上拖 = 变高），
> 高度记在浏览器里，下次打开还是你调过的高度。**双击那条横杠**则在「展开 / 收起」两档之间来回切。
> 色条本身也从 17px 加粗到 22px，关键帧菱形跟着放大了一档。

舞台上，**当前机位**会画出一条紫色虚线**运镜轨迹**（关键帧是线上的小方块）。
环绕类运镜的轨迹是**真圆弧**，不是把关键帧用直线连起来的多边形 ——
可以直接从这条线看出镜头到底怎么走。只画当前机位，免得机位一多就满屏是线。

左栏「动作模板」和「运镜模板」里的**分组标题可以点一下收起 / 展开**（标题右边那个数字是该组的条数），
动作多的时候先收起暂时不用的那两组，走位模板和图层就不用往下翻很久了。

## 技术说明（镜头视角是怎么算的）

- **俯视图**：世界坐标 = 背景图像素坐标，直接按缩放/平移变换绘制。
- **镜头渲染（两种模式共用同一套相机管线）**：把俯视背景图当作**地面贴图**，用**针孔相机模型逐像素逆映射**成透视画面（支持偏航、俯仰、高度、视场角、远景雾化）。
  - **3D 透视**：人物骨架放进真实 3D 空间（局部 u=前方 / v=右侧 / w=竖直），每个关节段投影后画成**带透视宽度的四边形**，横向用渐变模拟圆柱受光；头是径向渐变球；地面投影是按地面圆投影出来的多边形。远近按深度排序，所以镜头怎么转都对。
  - **2D 平面**：走**正交投影**（`renderShotOrtho`），不套针孔模型。横向按"相对相机的左右偏移 × 标定缩放"线性映射，纵向按世界高度线性映射，脚底统一落在地面线；无消失点、无近大远小，人物画成**平面剪影**（左右朝向由"角色朝向 · 镜头右侧轴"的点积决定），并叠画 `1m…8m` 高度参考线和相机视高线。
- **人物骨架（两种模式共用同一套姿态函数）**：44 个动作里有 38 个是**参数化姿态函数**（另外 6 个转身动作改的是朝向、不摆姿势），输出 12 个关节角，再按"髋→躯干→颈→头 + 两条腿 + 两条臂"串出骨架。
  局部坐标 y 向下为正、脚底在原点，所以**四肢用 `skStep`（`+cos`，朝下走），躯干用 `skStepUp`（`-cos`，朝上走）**；
  骨架各段长度之和为 `BODY_H = 1.053`，据此换算缩放，保证画出来的人物高度就等于传入的 `hpx`。
  **脚要踩地**靠 `groundY(hipL, kneeL, hipR, kneeR)`：由两条腿的角度反算「最沉的那条腿正好落地」所需的 `rootY`。
  沉身一律用**屈膝**而不是整体升降 —— 整体升降会把脚一起拽到地面以下。
  3D 和 2D 共用同一套 `actionPose`，所以加动作只需要写一个公式，两边同时生效。
- **朝向标记（三层，见前面「怎么看出人物朝哪儿」）**：
  - 俯视的箭头和鼻尖弧由 `drawCharTop` 画；视线扇形是**地面图形**（`gazeSector` 出多边形顶点），
    俯视按世界坐标直画、3D 用 `projPt` 投到 z=0，2D 平面**不画**（立面侧视图没有地面）。
    扇形铺在角色**下面**（渲染顺序上先统一铺一层），否则会把小人盖住。
  - 3D 的肩线沿 v 轴（身体左右）横在躯干上；脚尖朝 +u（正前方）；
    **鼻尖要按深度排序**（`nf > hf` 时先画鼻尖再画头，否则背对镜头时它会穿到脸前、把朝向说反）；
    两眼用「朝向 · 镜头前向」的点积淡入，正脸朝镜头时才出现。
  - 3D 人物是**圆柱段 + 球头**，绕自身轴转一圈轮廓不变 —— 不加这些不对称特征，
    正脸 / 后背 / 侧面在 3D 里完全一样。
- **转身片段的 `sweep`（有向扫角）**：通用的 `lerpAngle` 取**最短弧**，而 ±180° 是它的歧义点
  （`((b-a+π) mod 2π) - π` 把 `+π` 和 `-π` 都归一成 `-π`），于是「右转 180°」会往左扫。
  所以转身片段除了 `from` / `to` 还存 `sweep`，求值按 `from + sweep × 缓动`，**方向由动作定死**。
  `to` 保持绝对值（供界面显示和存档），与 `sweep` 解耦。老工程没有 `sweep`，回退最短弧。
  俯视的旋转手柄拖动时也同步改 `sweep`（否则拖出来的方向和面板插的不一致）。
- **3D 观察视图**：同一套渲染管线，只是相机换成"绕目标点球坐标"的自由机位；鼠标射线打到地面（z=0）来做拾取和拖动。
  该视图**恒用 3D 透视 + 立体人物**，不受顶栏「画面」开关影响。
- **视频导出**：`canvas.captureStream()` + `MediaRecorder` 实时录制，不引入 ffmpeg。
- **相机 / 走位的圆弧插值**：关键帧之间默认是**直线插值**（`lerp` x/y）。环绕类运镜和
  「环绕一圈」走位会额外在关键帧上挂一个圆心 `arc: {cx, cy}`；求值时若相邻两点
  挂着同一个「都有 `arc`」的标记，段内就改走**极坐标**（`core.js` 的 `arcPoint`）：
  角度按 `atan2` 算出差值、归一成 `(-π, π]` 后按 `e` 插值，**半径也各自插值**。
  于是：
  - 半径两端相同 → 正圆弧；两端不同 → **螺旋 / 弧形上升**，同一个机制全覆盖。
  - 圆心两端不同 → 圆心本身按 `e` 线性插值，所以 `camMove` 平移中的圆**仍是圆**，
    只是圆心在跟着移动。
  - 走位类（角色）的切线用**数值差分**求（`pathTangent` 取 `u` 与 `u+.004` 两点方向），
    而不是拿弦方向当切线 —— 12 段的圆里弦与切线差半个圆心角（15°），照抄弦方向
    角色会一边走一边来回摆。
  - 关键帧的 `arc` 是**每个键各一个对象**（共用一个的话，整体平移会把圆心累加 N 次）。
  - 手动改某一帧的 X/Y 会**摘掉 `arc`**，相邻两段退回直线 —— 用户亲手改过的那一帧
    就不再是完美圆弧的一部分了，这是应有的结果。
  - **画出来的线也按弧采样**（`pathPolyline` / `camTrail`）：走位线和当前机位的运镜轨迹
    都会按弧加密后再描边，否则「动作是圆、画的是多边形」，图和动作对不上。
    可编辑的方块仍落在原始路径点上。当前机位的轨迹是**新画出来的** ——
    以前画布上根本没有一条线能让你确认镜头走的是什么。

## 常见问题

**Q：双击打开是一片空白？**
请用 Chrome 或 Edge 打开。文件是纯静态的，但需要浏览器支持 Canvas 2D（现代浏览器都支持）。

**Q：3D 模式和 2D 模式到底差在哪？**
3D 是**透视投影**：地面有消失点、远处变小、人物是有体积的立体骨架（圆柱 + 球头 + 受光渐变），镜头转到侧面、俯视、仰视都成立。
2D 是**正交投影的立面侧视图**：没有消失点、没有透视地面、远处不变小，人物是永远正对镜头的平面剪影，还带 `1m…8m` 高度参考线和相机视高线——适合快速出分镜草图、目测人物与机位的高度关系。
两者共用同一套走位、动作和运镜数据，随时可以切换对比。

**Q：为什么我在俯视编辑下切 3D/2D，画面好像没变？**
因为俯视编辑画的是**俯视符号**（圆 + 朝向楔形），它表示"人站在这个位置、朝这个方向"，与"镜头拍成什么样"无关。
想看差别请切到 **3D 观察**舞台，或直接看右栏的**镜头预览**。

**Q：切 2D 之后，3D 观察舞台为什么还是立体的？**
故意的。「画面」开关只管**成片画面**（预览 / 预演 / 导出），3D 观察是编辑器的立体巡检视图。
如果让 3D 观察也跟着切成平面剪影，那些平面薄片被侧着看会变成贴在地上的细棍，反而像是坏了。

**Q：在「3D 观察」里拖动，视角转不动？**
两个已知原因，都不需要重启：

1. **镜头预演窗口开着**。它是全屏模态，会盖住整个舞台，指针根本到不了舞台。关掉它（`Esc` 或「关闭」）就能转。
2. **当前选中了某个绘制工具**（放角色 / 放机位 / 走位线 / 擦除）。以前这些工具会抢走拖动，
   现在已修：在 3D 观察里**拖动永远是转视角**，工具只在**轻点（不拖动）**时生效。
   舞台左上角 HUD 会提示 `工具：画走位线（拖动仍是转视角，轻点才生效）`。

另外注意：**在物体上起拖是移动物体**，不是转视角——想转视角请从空地起拖。

**Q：3D 观察视图的操作都有哪些？**
拖动＝环绕旋转，滚轮＝推拉，`Shift`+拖动或中键拖动＝平移；拖动角色/机位＝在场景里移动它。
无论当前选了什么工具，**拖动都保证是转视角**，工具只在轻点时生效。

**Q：导出视频时要注意什么？**
录制是实时的（时长 = 时间轴时长），期间**不要切走标签页**，否则浏览器会降频导致掉帧。建议先在「预览镜头视频」里用 960×540 试一遍。
存到哪里在顶栏「导出位置」里定一次就行（默认记住文件夹、不弹窗），临时换地方按 `Shift` 点导出按钮。

**Q：人物看起来是个火柴人？**
是的。3D 模式下是"带体积的火柴人"（圆柱骨架 + 球头），2D 模式下是平面剪影——分镜阶段用来交代走位、动作和构图已经够了。动作是**参数化姿态函数**，想加新动作只要在 `js/actions.js` 里加一条公式，3D/2D 会自动同时支持。

**Q：怎么一眼看出人物朝哪儿？**
三层标记，按看的远近各管一段：**视线扇形**（远看，扇形铺到哪就是它视野到哪）、
**箭头 + 鼻尖弧**（中景，圆外一支带白描边的箭头，圆上一段加粗白弧标"脸在哪边"）、
**肩线 / 脚尖 / 鼻尖 / 两眼**（3D 放大看，正脸有两只眼、背对是光球、侧面鼻子朝一边）。
还是嫌小就开**镜头预演**，用滚轮放大看 —— 缩放只改显示尺寸，不影响出片。
更省事的办法：**直接双击右下角那块镜头预览**，弹出「放大观察」大浮层，
滚轮缩放、拖动平移、点 `1:1` 按像素直显（会自动对准人），`Esc` 退出。
对照图见 `截图/朝向/`。

**Q：为什么「左转 180°」和「右转 180°」以前是同一个效果？**
因为通用的角度插值走的是**最短弧**，而 ±180° 恰好是最短弧的**歧义点** ——
`+180°` 和 `-180°` 归一之后是同一个值，于是两个按钮双双扫向同一侧。
现在转身片段会显式存一个**有向扫角**（往画面左还是往右），方向由动作自己定死，不再让插值函数去猜。
（90° 的两条不受影响，所以只有 180° 那两条会坏。）

**Q：背景图很大，会不会卡？**
导入的图建议不超过 4000px。透视渲染按半分辨率计算地面，一般机器 1080p/30fps 没问题。

**Q：能导出 GIF / 分镜接触表吗？**
当前版本没有，视频导出后可以自行转 GIF。

**Q：两个「辅助线」勾选框是同一个开关吗？**
不是，互相独立。右栏「镜头预览」下面那个只管小预览窗；预演大窗口顶部的那个只管预演画面。
导出时一律不画辅助线。两者互不影响。

**Q：动作面板太长，翻不到下面的「走位模板」怎么办？**
点分组标题就能收起那一组。分组状态只在本次会话里记着，刷新页面会恢复成全部展开。

**Q：为什么「希区柯克变焦」要用「推近 + 放大视角」这种反直觉的组合？**
因为要的效果是**主体大小不变、背景被抽走**。距离变近主体本来会变大，只有同时把视角放大
才能把主体"按"回原来大小；而背景离得远，距离几乎没变，视角一放大它就被推远了。
两者相抵，主体不动、背景变化 —— 这就是眩晕感的来源。反向版（后退 + 收窄视角）让背景反而被推近。

**Q：加了新动作之后，以前存的工程还能打开吗？**
能。动作是靠 id 存的，原有 16 个动作的 id 一个都没改。运镜模板只是"生成关键帧的快捷方式"，
工程里存的是生成出来的关键帧本身，所以「环绕主体」改成「环绕一圈」（120° → 360°）也不影响老工程。

**Q：有些动作的脚看起来轻微悬空？**
个别动作（闪避、奔跑、冲刺）在极端帧上脚会离地 2%~7% 身高，这是参数化姿态的取舍：
宁可略微悬空也不让脚穿到地面以下。新加的动作都用了「最沉的那条腿踩地」的算法，
实测脚下陷 ≤ 0.3% 身高。如果你觉得某个动作脚感不对，在 `js/actions.js` 里把 `rootY` 换成
`groundY(hipL, kneeL, hipR, kneeR)` 就能自动贴地。

**Q：AI 编排报「连不上 AI 代理」？**
代理没起。到工具目录双击 **`启动AI.bat`**（会另开一个窗口，那个窗口要一直开着）。
它需要 Node.js 18+，但**不用 `npm install`** —— 代理只用 Node 内置模块。

**Q：AI 编排一直显示「排队中」？**
你的 ComfyUI 正在跑视频。ComfyUI 的 `/prompt` 是先进先出，AI 请求只能排在后面，
面板会显示前面还有几个任务。等不及点「取消」即可 —— 它**只会撤掉自己排的那个**，
不会打断你正在跑的视频。想完全避开就先把视频任务跑完再改分镜。

**Q：模型说「场景里没有男主」，但我明明有角色？**
模型只会用**场景里真实存在的名字**。如果你在示例场景里（角色叫「角色A」）说「男主」，
场景里只有一个角色时它会自动对应过去；角色多的时候就分不清了。
直接说场景里的名字（或先让它「加一个男主」）最稳。

**Q：AI 改错了怎么办？**
按 **Ctrl+Z**。整批操作只占**一个撤销点**，一次撤销回到改之前。
面板里也会逐条列出 ✓/✗ —— 单条失败不会影响其他条，不用整批重来。

**Q：能不能不装 Node、不启代理？**
能，AI 编排是纯可选项。直接双击 `index.html` 用，其他功能一个都不少。

**Q：用云端 API 填什么？**
Base URL 填到 `/v1` 为止（例如 `https://api.deepseek.com/v1`），再填 API Key 和模型名。
点「测试连接」会先保存、再发一句极短的话试通。
报 404 基本就是地址或模型名不对；401 是 Key 不对；429 是限流。

**Q：本地模型老是「没有输出可解析的 JSON」？**
多半是**思考过程把 token 预算吃光了**，正文被截断。
面板设置里把「关闭思考」设成「强制开」（Qwen3 系默认已经自动开），
并把 `max_tokens` 提到 2400 以上。实测关掉思考后单次从 5s 降到 1.5s，也不再截断。

**Q：说了「让这个镜头在后拉的同时往上」，结果原来的后拉没了？**
说明模型用了 `shot`（会切掉它开始时间点之后的旧关键帧）而不是 `camMove`（叠加）。
现在 prompt 里写明了判断依据（看那台机位「关键帧 N 个」，为 0 就是新做一段），
实测能稳定选对。真出现这种情况按 **Ctrl+Z** 撤销重说一次即可。

**Q：AI 把整个场景搞乱了？**
按 **Ctrl+Z** 一次就能整批回退。用「整场替换」前会弹确认框 ——
那一步会清空现有角色/机位/片段，是这批里最不可逆的操作。

**Q：`ai-config.json` 会不会泄露我的 Key？**
不会。Key 只写在那个本机文件里，`/config` 和 `/health` 返回的都是打码版
（形如 `sk-t••••••cdef`）。前端页面的任何请求都拿不到明文。
（这条有专门的断言在守着，见 v1.6 验证记录。）

### v1.8 — 让朝向看得见 + 转身方向不能靠插值函数猜

**新功能**

- **朝向三层标记**（详见上面「怎么看出人物朝哪儿」）：
  - 俯视：圆外**带白描边的箭头**（让开旋转手柄）+ 圆上**白色鼻尖弧**
  - 俯视 / 预演：**视线扇形**（半径 4m、半张角 32°，地面图形，透视下投到 z=0），
    预演窗口可勾选，**导出不带**（编辑标记）
  - 3D：**肩线 / 脚尖 / 鼻尖 / 两眼** 四个不对称特征 —— 圆柱和球天然前后对称，
    不加这些的话正脸、后背、侧面在 3D 里长得一模一样
- **预演窗口可缩放**：`－` / `＋` / 百分比 / 适应，滚轮缩放、拖动平移。
  只改**显示尺寸**（内联 `width/height`），**画布分辨率不动**，所以存当前帧和录制导出
  仍然是选定的那个尺寸，不会跟着变小。缩放以**视口中心为锚点**，切分辨率自动重新适应。
  （**v1.9 起改为以指针为锚点** —— 见下。）
- 俯视角色的半径与旋转手柄距离抽成共用函数（`charRadius` / `rotHandleDist`）——
  以前两处一个 `max(10)` 一个 `max(12)`，手柄会跟角色大小对不上。

**修掉的问题**

1. **「左转和右转都是往右转」**（用户反馈）。
   根因是**通用角度插值取的是最短弧，而 ±180° 恰好是它的歧义点**：
   `((b-a+π) mod 2π) - π` 把 `+π` 和 `-π` 都归一成 `-π`，于是「右转 180°」也往左扫。
   数值实证：右转 180° 与左转 180° 的插值**终点都是 -180°、中点都是 -90°**。
   90° 的两条不受影响（`+π/2` 与 `-π/2` 不歧义）—— 所以只有 180° 那两条坏。
   → 转身片段显式存**有向扫角 `sweep`**，求值改按 `from + sweep × 缓动`；
   `to` 与 `sweep` 解耦（`to` 保留绝对方位供界面/存档显示）；老工程无 `sweep` 回退最短弧。
   三处建片段的地方（面板插入 / 拖拽旋转手柄 / AI 的 `face`）都写 `sweep`。
   **这个 bug 只看终点抓不到**（±180° 本就是同一方向），必须量中间时刻 ——
   新增探针 `p12_turn` 专测中点：修后右转 180° 中点 `+90°`、左转 180° 中点 `-90°`。
2. **回归从 0 项暴增到 72 项**（修 1 的过程中暴露出来的，四条独立原因叠在一起）：
   - **`p10_follow` 从不还原场景**。它测完跟随运镜就把自己造的角色「戊」和带 9 个关键帧的机位
     留在全局状态里，后面的 `p2_render` 一直拿这个残留场景做断言 —— 也就是说
     **p2 的覆盖率一直是假的**，它从没测过真正的开机场景。修：存引用 + 结尾还原 + `refreshAll()`。
   - **正交雾化的单位错了**。`renderShotOrtho` 里 `o.dep` 已经是**世界像素**（上游就是拿世界

   - **`to = from + sweep` 把绝对目标角度改了**。`turnFront` 的目标本来是 `180°`，

   - **剪影断言卡了 alpha**。`drawFigure` 故意把「远侧」肢体画成 72% 不透明（透视暗示），

   排查手法：给 `verify.js` 加 `only` 过滤参数（`node verify.js p12,p2_render`）做二分 →
   插一个临时诊断探针卡在 `p2` 之前打印现场 → 定位到「谁把状态弄脏了」。
3. **剪影断言一直在跑，量的却不是剪影**（修 2 之后剩下的最后 1 项）。

### v1.7 — 转身动作 + 「跟随吃掉运镜」+ 整场替换兜底 + 环绕走真圆弧

**新功能**

- **动作面板新增「转身」组（6 条）**：左转 / 右转 90°、左转 / 右转 180°、
  转身面向镜头、转身背对镜头。它们不摆姿势，改的是**朝向** ——
  插进去的是一段**转身片段**，和拖着角色旋转手柄、AI 的 `face` 操作走同一条路，
  所以渲染 / 时间轴 / 属性面板都不用改。相对角度按**当前朝向**算，连点两次真的转两次。
- AI 的 `act` 操作同样能用这几条（提示词里已注明它们改的是朝向、角度按当前朝向算）。

**修掉的问题**

1. **「跟随」把运镜整个吃掉**（用户反馈：「模型好像不理解什么是摄像头以圆形移动」）。
   先查了模型 —— 写了 5 种说法 × 5 种场景条件的探针，**模型每次都选对了 `orbit`**，
   不是它的问题。真因在渲染层：`evalCam` 里 `cam.follow` 会**整个覆盖**
   关键帧算出来的 `x / y / angle`，而 `insertCamTemplate` 只在**跟随类**模板上才动
   `cam.follow` → 在一台跟随某角色的机位上套任何自主运镜（环绕一圈 / 推进 / 横摇 /
   螺旋 / 弧形上升…），**键全都在、画面却纹丝不动**，日志还写着 ✓ 环绕一圈。
   → 规则改成「**跟随和关键帧二选一**」：非跟随模板插进来时把 `follow` 清掉，
   并在提示里写明「已关闭跟随、改用关键帧」。
   探针带**对照组**坐实：同一个 `orbit`，非跟随机位 `spanX=756`、跟随机位 `spanX=400`
   （半径本就不同），但两者的「周长/直径比」完全一致 —— 形状不受跟随影响，
   跟随不再干扰运镜。（这个比值当时是 `0.9745`，被我当成了「正常」；
   它其实是**内接八边形的周长比**，真圆该是 `1.0000` —— 见下面第 7 条。）
2. **`target` 指成机位自己，绕圈退化成 80px 的小圈**。模型在「场上只有机位、
   没有角色」时会把这台机位的名字填进 `target`，于是 `orbit` 以**镜头自己**为圆心，
   半径只剩 `0.8m`（直径 80px），画面上几乎看不出在动。
   → ① `shot` 只把**角色**认作主体，`target` 是机位就当没给；
   ② `tgtOrAhead` 再加一道兜底：主体离镜头不到半米也当没给，退回「镜头正前方 4m」。
   修完直径回到 400px。
3. **跟随机位上的水平平移是「假成功」**。`camMove` 只对**上下**做了跟随特判
   （改 `follow.height`），水平方向照旧去改关键帧 —— 而跟随机位的 `x/y` 每帧由目标算出来，
   那些键永远不会生效，日志却写着「平移 2m」。→ 先把「当前跟随到哪儿」烘成一个关键帧，
   再关掉跟随、照常偏移，日志写明「原来是跟随机位，已改为关键帧控制」。
4. **同一时刻重复套运镜会静默吃掉前一段**。用户贴一段分镜描述时，模型一口气写了
   3 条 `shot` 挤在 0.8~1.3s，`insertCamTemplate` 会把 `t0` 之后的键全切掉，
   结果**只有最后一条完整生效**，日志里却三条都是 ✓，很容易误判成「都加上了」。
   → 覆盖本身是正常行为（后一条就该赢），但要说出来：提示里点名
   「它覆盖了『环绕一圈(0~4.0s)』在 1.0s 之后的部分」。干净接在上一段结束时刻不会触发。
5. **「整场替换」后场景空掉**（用户反馈：「我用整场替换，结果告诉我场景里啥都没有」）。
   替换模式**先清空再应用**，而摘要里有意不列旧对象，模型只能从用户指令里抄名字，
   于是 `act who=甲` 找不到对象 → 每条都失败，旧场景还已经没了。
   → ① 替换模式下加运行时上下文 `AI_REPLACE_CTX`：名字找不到就**按默认锚点建出来**，
   日志标注「（替换模式下自动新建了 甲(角色)）」；② 无机会位时自动补一台；
   ③ `del` 一个本来就没有的对象不再算错；④ 提示词明写「先建后用」的顺序规则；
   ⑤ **一条都没落地就整体回滚** —— 不能让用户「旧场景没了、新场景也没搭起来」。
6. **报错信息看不出错在哪**。模型会把别的表里的 id 串用（最典型：`arc` 在**走位模板**里，
   不在运镜里），而报错只说「没有这个运镜：arc」。→ 报错点出「它是什么」
   （走位模板 / 动作 / 运镜）+ 列出可用清单，模型和用户都能照着改。
7. **环绕的路线不是圈，是多边形**（用户反馈：「你现在摄像机的环绕的路线不是圈，而是多边形」）。
   这条是**我自己上一轮漏掉的**：真因是 `evalCam` 在相邻关键帧之间做**直线插值**（`lerp` x/y），
   于是 9 个键的「环绕一圈」连出来是**内接八边形**。两个后果：
   ① 段中点到圆心只有 `R·cos(22.5°) = 0.924R` → 镜头忽远忽近，主体在画面里
   大小脉动 7.6%；② 周长只有真圆的 `sin(π/8)/(π/8) = 0.9745`。
   **我上一轮还把这个 `0.9745` 当成「正常」写进了断言和文档** —— 等于把 bug 当成了正确行为。
   → 在**求值层**加一层圆弧插值：给关键帧（走位则是给片段）挂圆心 `arc: {cx, cy}`，
   同一圆心上相邻两点之间改走**极坐标**（角度 + 半径各自插值），多边形就变成真圆弧。
   - 半径允许两端不同 → 螺旋环绕（边绕边靠近）、弧形上升**同一个机制**就覆盖了。
   - 圆心也允许两端不同（`arcPoint` 里按 `e` 线性插值）→ `camMove` 平移中的圆
     仍是圆，只是圆心在移动；不然「移完之后圈散架」。
   - 环绕类的 `ease` 必须是 `linear`：每段都给 `inout` 的话，一圈里会**一冲一停八次**。
   - `arc` 要在循环里**每个键各建一个对象** —— 共用一个的话，整体平移会把圆心累加 N 次。
   - 角色走位的**朝向**不能拿弦方向当切线（12 段的圆里弦与切线差 15°，角色会来回摆），
     改用数值差分求真切线。
   - **手动改某一帧的 X/Y 要摘掉 `arc`**：用户亲手改过这一帧，它就不再是完美圆弧的一部分，
     相邻两段退回直线 —— 这是正确结果，不是妥协。不摘的话弧插值会无视刚拖到的位置
     （又一个「拖了没反应」的静默失效）。
   修前 / 修后的硬证据（同一个 `orbit`，p10 的 `roundness`）：

   | | 周长 path | 周长/直径比 |
   |---|---|---|
   | 修前（内接八边形） | 2314.5 | **0.9745** |
   | 修后（真圆弧） | 2373.3 | **0.9993** |

   新增探针 `p11_arc`：`orbit` 半径比 `1.0000`、每段圆心角 45°、角速度峰均比 `1.00`；
   `spiralIn`/`arcRise` 半径**单调**（回摆 0 次）；角色环绕半径比 `1.0000`、
   朝向贴合真切线误差 `0.72°`、转满 `359.9°`；`camMove` 平移后圆心漂移 `0.01px`。
   对照组：`dollyIn` / `handheld` **不带** `arc`，且推进的中点必须落在两端点的中点
   （直线插值的指纹）—— 保证没把不该改的顺手改成弧。
   另外**画布上的线也按弧采样**（`pathPolyline` / `camTrail`），并新增「当前机位的
   运镜轨迹」显示：以前画布上根本没有一条线能让你确认镜头走的是什么。
   还专门验了 `arc` 这层新状态**扛得住存档往返、撤销重做、3D 观察视图、关键帧列表** ——
   序列化里只要有一处「按字段逐个拷贝」，它就会静默消失、环绕又变回多边形。

**验证**：全量无头回归 p1~p11 **断言失败 0 项、未捕获异常 0 条**（p10 专治跟随、
p11 专治环绕走折线）；云端 API 通道 24/24；真模型多轮 **8/8 通过**，其中「重新搭一场：角色站中间、
机位跟随他、再做推进」这步的日志是
`✓ shot — 给「机位1」在 0.0s 加运镜 推进（原来是跟随机位，已关闭跟随、改用关键帧）`。

**修掉的问题**

1. **`camMove` 水平方向把「米」当「像素」用**。`height` 的单位是米，而关键帧里的

   肉眼几乎看不出来。→ 水平分量乘上 `App.state.pxPerMeter`。
2. **`insertCamTemplate` 在起点留下重复关键帧**。过滤条件是 `k.t <= t0`，
   紧接着又在 `t0` 插一个新键 → 同一时刻两个键：画面上两个重叠标记，
   `evalCam` 也只会用到后一个。→ 改成严格小于 `k.t < t0`。
   新键的状态取自过滤**之前**算好的 `evalCam(cam, t0)`，信息不丢。
3. **`/test` 忽略请求体里的 `provider`**，只测「配置文件里已保存的那条通道」。
   前端因为「先保存再测」才碰巧能用。→ `/test` 认 `body.provider`，
   不传时才回落到配置文件。
4. **`looksLikeFmt` 正则过宽**。里面写了 `unsupported|not support`，于是

   走错降级分支、白试一次。→ 只匹配字段名本身（`response_format|json_object|json mode`）。
   宁可漏判（用户看到原始报错）也不要误判。
5. **思考模型把 token 预算耗光，JSON 一个字吐不出来**。提示词一复杂，

   → 本地通道给 Qwen 系自动加 `/no_think`（**5.1s / 377 字 → 1.5s / 37 字**），
   并把默认 `max_tokens` 从 1200 提到 2400 兜底。设置面板里可强制开/关。
6. **「接在后面」把新内容推到 2 倍位置**。场景摘要里写着「已排到 6.6s」，

   应用时再加一次 T，新镜头落到 13.2s，中间空一大段。
   → 追加模式下摘要**不再显示时间线末尾**，只说「已有内容你不用管，从 0 编号」。
7. **「整场替换」时模型对着旧对象清单纠结**。它反复琢磨「要不要先 del 掉」

   只给画布尺寸，明说「对你是空的」。
8. **`camMove` 的秒数是让模型算的，它会算错**。示例里写的是 `at:0`，模型照抄 ——
   于是「在后拉的同时往上升」变成了「先升高、再后拉」（位移跑到时间线开头），
   而且**时好时坏**（连跑两次一次对一次错）。
   → 改成 `at` / `dur` **默认不写**，省略时自动对齐到这台机位最近一段运镜的窗口，
   由代码算（和「接在后面」同一个教训：能让代码算的就别让模型算）。
   示例里也去掉了 `at`，并加了断言守住这个回归。修完连跑 3 次全部落在 4.1~6.6s。
9. **`camMove` 自己给自己找台阶**。显式给了秒数、但那段和已有运镜毫无重叠时，
   以前会静默照做，看起来像「叠上了」其实没有。→ 日志追加
   「（注意：这段没和已有运镜重叠）」；重叠时不会出现这句。

### v1.5 — 接本地模型：一句话改分镜

**需求**：让 ComfyUI 里跑的本地模型替我在这个工具里搭场景（自然语言增量修改）。

**做法**：不让模型直接吐工具的存档 JSON（像素坐标 + 深层结构，8B 模型扛不住），
中间加一层**意图 DSL**：模型只说「谁、做什么、在哪个方位、第几秒」，
方位用 `center` / `north` / `west` 这类词，**由工具换算成像素**。

- `js/ai.js`（新）：意图 DSL 定义、prompt 组装、JSON 校验、应用到 `App.state`、面板 UI
- `ai-proxy.js`（新，Node 零依赖）：连 ComfyUI 的 llama-cpp，剥 ` thinking`、修 JSON
- `启动AI.bat`（新）
- 支持 11 种操作：`addChar / addCam / del / shift / moveTo / moveStyle / act / face / shot / set / clear`

**两个踩出来的关键点**

1. **必须过代理，浏览器直连一定失败**：工具是 `file://` 打开的，页面 Origin 是字符串 `null`，
   而 ComfyUI 完全不发 CORS 头（实测 `Access-Control-Allow-Origin` 一个都没有）。
2. **工作流末尾必须挂 `PreviewAny`**：`llama_cpp_instruct_adv` 返回的 STRING 没带 `ui` 字段，
   ComfyUI 不会把它放进 `/history` 的 `outputs`（实测不加这个节点，`outputs` 是空的）。
   挂一个 KJNodes 的 `PreviewAny`（`output_node: true`）才读得到文本。

**顺带重构**：把界面上的「插入动作 / 走位 / 运镜」抽成
`insertActionClip` / `insertMoveClip` / `insertCamTemplate` 三个共用函数，

### v1.3.1 — 「3D 观察」里拖动转不了视角

**用户报障**：「现在 3D 也转不了视角了」

**根因（两层）**

1. **工具抢走了拖动**。`onDown3D()` 里工具分支排在环绕分支**之前**，而且每个分支都直接 `return`：

   ```js
   if (App.tool === 'char')  { ...放角色... return; }   // ← 拖一下 = 放一个角色
   if (App.tool === 'cam')   { ...放机位... return; }
   if (App.tool === 'erase') { ...删除...   return; }
   if (App.tool === 'path')  { ...打点...   return; }   // ← 拖一下 = 打个走位点
   ...
   App.drag = { mode: 'orbit', ... };                   // ← 永远到不了这里
   ```

   只要当前不是「选择」工具，在 3D 观察里拖动就**完全转不了视角**。

2. **`finishPath()` 不复位工具**。画完走位线（双击或回车结束）后 `App.tool` 仍然停在 `'path'`，
   于是"画完走位线 → 去 3D 看看效果 → 拖不动"变成一条必踩的路径。

实测复现（修复前）：

| 当前工具 | 3D 里拖动 | 结果 |
|---|---|---|
| 选择 | `drag.mode=orbit` | ✅ yaw −0.611 → −1.571 |
| 走位线 | `drag.mode=null` | ❌ 不转 |
| 角色 | — | ❌ 不转，还**误放了一个角色**（物体数 3→4） |
| 机位 | — | ❌ 不转，还**误放了一个机位**（物体数 3→4） |
| 擦除 | `drag.mode=null` | ❌ 不转 |

**修复**

- 把四个工具分支抽成 `run3DTool(tool, sx, sy)`，从 `pointerdown` 挪到 `pointerup` 执行。
- 新增 `toolclick` 中间态：非「选择」工具按下时先挂起；**移动超过 4px 就升级成环绕旋转**（升级时把起点重设到当前位置，避免视角跳一下）；全程没动才算"点击"，此时才执行工具动作。
- `finishPath()` 结束时 `setTool('select')`。
- 3D 舞台 HUD 在非「选择」工具时显示 `工具：xxx（拖动仍是转视角，轻点才生效）`。

修复后实测：

| 当前工具 | 拖动 | 轻点 |
|---|---|---|
| 选择 | ✅ 转视角 | — |
| 走位线 | ✅ 转视角，不打点 | ✅ 正常打点 |
| 角色 | ✅ 转视角，不放角色 | ✅ 正常放置，工具自动复位 |
| 机位 | ✅ 转视角，不放机位 | ✅ 正常放置，工具自动复位 |
| 擦除 | ✅ 转视角，不删东西 | ✅ 正常删除 |

### v1.3.1 附带修复 — 点空白处取消选中会抛未捕获异常

排查上面那个问题时用 CDP 的 `Runtime.exceptionThrown` 抓堆栈，发现每次**点空白处取消选中**都会抛一次：

```
Uncaught TypeError: Cannot read properties of null (reading 'clipId')
    renderTimeline  ui.js:581
    refreshAll      ui.js:1456
    onDown3D        ui.js:883   ← App.sel = null; refreshAll();
    onDown          ui.js:725
```

`renderTimeline()` 遍历的是**所有对象**（不是选中对象），所以取消选中后也会被调到这里，
但它直接读了 `App.sel.clipId` / `App.sel.keyId`，没有空值保护。

**影响比看上去大**：`renderTimeline()` 在 `refreshAll()` 里排第 4 位，后面还有
`updateTimeUI / updatePlayhead / draw / updateHud / renderPreview` —— 异常会把它们**全部跳过**，
所以点空白处取消选中时那一帧的画布、HUD、预览都不会更新。

**修复**：在 `renderTimeline()` 开头取一次快照 `const selClip = App.sel ? App.sel.clipId : null;`（keyId 同理）再用于比较。
顺带把全项目 `App.sel.` 的访问都过了一遍，其余都在 `if (!o) return` 之后，是安全的。

> 这类 bug 在 `file://` 下很难发现：脚本被当作跨域，`window.onerror` 只给一句
> `Script error. @0:0`，没有堆栈。**要用 CDP 的 `Runtime.exceptionThrown` 事件才能拿到完整调用栈。**

### v1.3 — 2D 改为真正的平面视角 + 人物"倒栽"bug

**① 「画面」开关以前只换人物，不换画面**（用户报障："3d切2d还是不行啊，只是人物变了"）

原来的 2D 模式只是把人物换成平面剪影，**地面和取景仍然是透视的**，所以整幅画面看起来还是 3D。
现在 2D 模式走**正交投影立面侧视图**：没有消失点、没有透视地面、远处不变小，并补上 `1m…8m` 高度参考线与相机视高线。
新增 `orthoBasis()` / `drawFigureOrtho()` / `renderShotOrtho()`（`js/render.js`），`renderShot()` 顶部按 `opts.ortho` 分派。

同时把开关的语义和名字都改清楚了：
- 顶栏标签 `人物` → `画面`，按钮 `3D 立体` → `3D 透视`
- 作用范围收敛为**成片画面**（预览 / 预演 / 导出），不再影响 3D 观察舞台
- 3D 观察舞台改为恒用立体人物（`mode: '3d'`）——否则切 2D 时平面薄片被侧着看会变成贴地细棍
- 舞台 HUD 文案：`3D 观察（恒为立体场景）　镜头画面 2D 平面　…`

**② 人物是"倒栽"的——头长在脚边**（查证 ① 时发现，从 v1 就存在的隐藏 bug）

`drawFigure()` 里躯干和四肢共用了同一个 `skStep()`，而这个函数的竖直分量是 `+cos`（朝下）。
四肢用它是对的（髋 → 膝 → 踝一路向下踩到地面），但**躯干也朝下就反了**：脖子落在髋的下方，头贴到脚边。

对比 `buildSkeleton3D()`（3D 模式）就能看出不一致——那里躯干用 `+cos`（向上）、四肢用 `-cos`（向下），是对的。
所以这个 bug 只在 2D 剪影路径上可见，3D 模式一直正常，之前没被发现。

修复：新增 `skStepUp()`（竖直分量取负，水平分量保持 `sin(deg)`，使 `torso` 正负含义与 3D 一致），躯干和头改用它。

顺带修正了**人物画出来比配置身高高 5.3%** 的问题：骨架各段长度之和是 1.053 而不是 1，
新增 `BODY_H` 常量并据此换算缩放，使 `hpx` 就是脚底→头顶的实际高度。

实测（配 1.75m 站立）：
| 项 | 修复前 | 修复后 |
|---|---|---|
| 头顶归一化高度 | 0.083（头在脚边） | 1.053 ✅ |
| 头顶离地 | 87px | 139px（≈1.74m，差 0.6% 来自姿态前倾） |
| 1m/2m/3m/4m 参考线 | — | y=298/218/138/58，与期望逐项吻合 ✅ |
| 名称标签位置 | 飘在头顶上方 40 多 px 的空中 | 紧贴头顶上方 ✅ |
